# Canada FIRE Calculator UI contract

The authoritative design is `/Users/leo/Code/project-devlog/projects/canada-fire-calculator/notes/ui-unify-2026-11-design-report.md`, sections 4–8. Its companion handover defines the PR boundaries. Reference screens and the screen manifest are in that project's `assets/design/ui-unify-2026-11/` directory.

`src/styles/tokens.css` contains the reference light and dormant dark tokens. Dark mode is not enabled automatically. Use `--surface`, `--surface-2`, `--ink`, `--ink-2`, `--ink-3`, one `--accent`, and the positive, caution and critical semantic families. Chart colors are resolved from these CSS tokens by `src/chartColors.ts`; account colors must agree between charts. No color literals belong in component styles.

Typography uses Inter and the display, title, heading, body, ui, meta, caption and micro steps. Display becomes 24px on phones; micro is reserved for status sublines in table cells. Spacing uses 4, 8, 12, 16, 24, 32 and 48px. Controls use 6px radii, panels 10px, sheets 16px and chips full rounding. Static panels have borders; only floating surfaces use the floating shadow. Focus uses `--focus-ring`; state transitions use the duration and easing tokens and respect reduced motion.

Shared primitives live in `src/ui/index.tsx`, with styles in `src/ui/ui.css`:

- `Button`: primary, secondary, ghost, danger and link; md and sm; disabled and width-preserving loading states; forwards refs and native button attributes.
- `Segmented`: equal-width button or tab mode. Button mode exposes `aria-pressed`; tab mode exposes `aria-selected` and roving focus with arrows, Home and End. Existing caller keyboard handlers take precedence when they prevent the event.
- `Field`: preserves a wrapping label or an explicit `htmlFor`, with `as="div"` for separately labelled controls. Validation and source text retain their existing associations.
- `ChoiceCard`: native radio or checkbox label, or pressed button. Selection uses the full border and an inset ring, with a tinted background.
- `StatusChip`: ok, est, unknown, bad and info. Keep localized status text; ok and bad also include an icon hidden from assistive technology.
- `Callout`: info, warn and example, full border and a decorative icon. The `as` prop preserves existing paragraph, fieldset or section semantics.
- `Disclosure`: native details/summary semantics, including existing controlled open state and onToggle handlers.
- `Sheet`: named modal dialog, scrim and Escape dismissal, trapped focus, scroll locking and trigger focus restoration; a desktop drawer and mobile bottom sheet.

Responsive widths are phone ≤640px, tablet 641–1099px and desktop ≥1100px. The guided questionnaire uses a 248px directory, up to 640px question column and 40px gaps; its 300px help rail appears at ≥1280px. The center column shrinks to fit at 1280px. Tablet uses a single column with the existing directory toggle. Container queries remain appropriate for narrow result and tax-facts columns. The annual table also retains its short-window height query so browser zoom cannot hide the table.

Compatibility class names and `data-testid` attributes remain on their original DOM elements. Calculations, capability gates, stored plan semantics, question order, reset confirmation, analytics events and annual-table accessibility names are unchanged. The foundation change applies tokens and control styling without introducing the later screen layouts.

Existing screen rules live in the `legacy` CSS layer. The default button display lives in the lower `primitives` layer, so screen visibility and directory row grids take precedence; shared visual styles remain unlayered. Keyboard focus paints a 2px accent ring above a 4px tint halo, with a system Highlight outline in forced colors. Disclosure headers use the 14px UI step from the fixed type scale; section 5's illustrative 15px value is outside that scale. Chart legend and tooltip labels use neutral text because some prescribed series colors meet the graphic contrast requirement but not the text requirement; their swatches retain the series colors.

The app shell and desktop questionnaire geometry live in `src/styles/shell.css`. `AppBar` uses existing store actions for mode, language and display basis. On phones the menu and language picker use the shared modal Sheet, with Escape dismissal and focus restoration. Canonical evidence entry appears in guided review and Professional mode. The full question help disclosure retains examples and source facts alongside the desktop summary rail. Programmatically focused question/review/result headings suppress the ring for that focus session; keyboard controls retain the shared visible focus treatment.

First-visit consent retains the unchanged full disclosure in normal flow immediately after the guided question heading on question routes, and early below the app bar elsewhere. At 390px in EN/FR/ZH, the first heading stays within 200px while both disclosure actions remain above the fold, including for privacy-eligible undecided visitors. The phone menu also shows the full disclosure before a grant; its hooks are distinct from the page prompt and footer. If a focused menu consent action unmounts, focus moves to the stable privacy heading inside the Sheet; Tab and Shift+Tab continue naturally from there, and Escape restores the menu opener. Sheet glossary actions close the Sheet before opening the existing drawer; the drawer contains keyboard focus and restores its activator. Its visual redesign remains assigned to PR-7. Canonical entry remains a standalone disclosure in guided review and Professional mode; PR-4 owns the review side card, and PR-6 owns the Advanced grouping.

Generated PR evidence is stored outside this repository, staged in scratch for the coordinator to place in the handover's devlog evidence directory. The reusable physical-Thorium Playwright configuration remains in the repository; CI uses its unchanged default configuration.

Validation: shared component Vitest tests exercise state, native labels and keyboard behavior, and modal dismissal and focus return. `tests/e2e/ui-contract.spec.ts` checks styled buttons, computed text contrast and horizontal overflow in all three languages. Existing feature E2E assertions remain authoritative.

Results navigation uses a 184px sticky Guided rail on desktop, a sticky underline strip in Professional Results and scrolling phone chips. These are section links with `aria-current`, not a second question tablist. `#results` remains the ResultPeek focus target. Section links retain the Guided route hash and focus `#results-{overview,balances,income,benefits,tax,strategies,risk,scenarios}` without scrolling the app shell. IntersectionObserver uses the nearest active overflow pane, or the viewport when results scroll with the document; it rebinds on resize. Gated sections appear only when their existing content is available. The withdrawal-order card remains in Overview in its original container.

Stable result selectors are `.results-column`, `.summary`, `.withdrawal-order-card`, existing test IDs, `[data-result-section]`, `.results-navigation a[aria-current="true"]`, `.chart-legend button[data-series][aria-pressed]` and `.chart-plot .recharts-wrapper`. Legend controls sit outside each chart's `role="img"`; hiding a series changes only its plot, keeping original tooltip values, totals, reference marks and narrative. The shortfall plot uses an SVG hatch and localized first-gap label. Charts are 250px on desktop/tablet and 200px on phones; compact axes use the narrow dollar symbol and a CAD caption. Chart colors continue to resolve through `chartColors.ts`.

Professional's tall conclusion scrolls with the content while its section navigation sticks. Existing input-revision handling still returns that pane to the conclusion when an input changes. This prevents a pinned conclusion from covering chart anchors. The annual-details rail button appears only in the desktop Guided rail; the existing overview action remains available in every mode. Long legends wrap below the title on narrow cards. `tests/e2e/results-navigation.spec.ts` adds the FE-66 results contracts for gates, responsive scroll roots, focus, tooltip preservation, series colors, hatching, three-language sizing and phone touch targets.
